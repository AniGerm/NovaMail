# NovaMail Engineering Standards

These rules apply to every change.

1. Never ship placeholders in product or IPC paths.
2. If a function is missing, implement a first real version.
3. Never fabricate mail/account data in the UI.
4. Prefer production-ready code: typed errors, validation, secure secrets.
5. Before creating a file, check for an existing module and improve it.
6. Keep clean architecture boundaries (see `ARCHITECTURE.md`).
7. Document decisions in `docs/adr/`.

See [ADR 0004](adr/0004-engineering-standards.md).
